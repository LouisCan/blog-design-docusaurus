# 如何新增一个类似 Tutorial2 的导航栏文档区

本文完整记录在 Docusaurus 站点中新增第二个文档导航栏（Tutorial2，内容指向 `docs2/` 目录）的全部操作步骤。整个过程只需要改动 **2 个配置文件、新建 1 个侧边栏文件、创建 1 个文档目录**，无需安装任何新依赖。

## 背景原理

Docusaurus 的 `@docusaurus/preset-classic` 预设内部只内置了**一个** docs 插件实例，它固定读取 `docs/` 目录、使用 `/docs` 路由前缀。因此导航栏里原有的 Tutorial 入口，实际上关联的是这个默认实例。

如果想要第二个文档区（比如 Tutorial2 → `docs2/` 目录），不能只在配置里改个路径，而必须在 `plugins` 中**额外注册一个 `@docusaurus/plugin-content-docs` 插件实例**。这个插件已经随 preset-classic 一起安装好了，直接引用即可，不需要 `npm install` 任何东西。

理解这一点后，接下来的操作就非常清晰了。

## 第一步：创建 docs2 目录和首篇文档

新建 `docs2/` 目录，并在其中创建第一个文档 `docs2/intro.mdx`：

```mdx
---
sidebar_position: 1
---

# Tutorial2 Intro

这是 docs2 目录的第一个文档。
```

:::note 注意

docs 插件实例要求其目录内**至少存在一个文档**，否则构建时会直接报错。所以首篇文档必须在配置插件之前（或同时）创建好。

:::

## 第二步：新建独立的侧边栏文件 sidebars2.js

在项目根目录新建 `sidebars2.js`（与原有的 `sidebars.js` 同级）：

```js
// @ts-check

// Sidebar dedicated to the second docs plugin instance (docs2/ directory).
// Docs plugin instances must NOT share the same sidebar file: each instance
// generates a sidebar for every key it finds, which leads to name clashes.
/**
 * @type {import('@docusaurus/plugin-content-docs').SidebarsConfig}
 */
const sidebars = {
  tutorial2Sidebar: [{type: 'autogenerated', dirName: '.'}],
};

export default sidebars;
```

其中 `dirName: '.'` 表示相对于本插件实例自己的 `path`（也就是 `docs2/`）自动生成侧边栏，`docs2/` 下的所有子目录和文档都会被自动收录。

:::warning 关键坑点：千万不要共用 sidebars.js

最初的做法是让两个插件实例共用同一个 `sidebars.js`，在里面同时定义 `tutorialSidebar` 和 `tutorial2Sidebar`。结果构建出来的页面里，点击导航栏 Tutorial2 跳转到的却是 `/docs/intro`（Tutorial 的页面）。

原因是：**每个 docs 插件实例都会为自己读到的侧边栏配置文件里的每一个 key 都生成一份 sidebar**。共用一个文件时，默认实例（`docs/`）也会生成一份 `tutorial2Sidebar`，导航栏的 `docSidebar` 类型导航项在解析时命中了默认实例的那一份，链接自然就指错了。

结论：**每个 docs 插件实例必须使用独立的 sidebar 文件**，文件内的 sidebarId 只在自己实例内生效。

:::

## 第三步：修改 docusaurus.config.js

需要改动两处。

### 3.1 注册第二个 docs 插件实例

在 `presets` 同级新增 `plugins` 字段：

```js
plugins: [
  [
    '@docusaurus/plugin-content-docs',
    /** @type {import('@docusaurus/plugin-content-docs').Options} */
    ({
      id: 'docs2',
      path: 'docs2',
      routeBasePath: 'docs2',
      sidebarPath: './sidebars2.js',
    }),
  ],
],
```

各参数含义：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `id` | `'docs2'` | 实例唯一标识，导航栏等处通过它引用本实例 |
| `path` | `'docs2'` | 文档内容目录（相对站点根目录） |
| `routeBasePath` | `'docs2'` | URL 路由前缀，最终访问地址为 `/docs2/...` |
| `sidebarPath` | `'./sidebars2.js'` | 本实例专属的侧边栏配置文件 |

:::warning 路由前缀不能冲突

`routeBasePath` 必须与默认实例的 `docs` 不同，否则两个实例会在 `/docs` 路径上发生路由冲突，构建报错。

:::

### 3.2 导航栏新增 Tutorial2 入口

在 `themeConfig.navbar.items` 中，紧跟原有的 Tutorial 项之后添加：

```js
navbar: {
  items: [
    {
      type: 'docSidebar',
      sidebarId: 'tutorialSidebar',
      position: 'left',
      label: 'Tutorial',
    },
    {
      type: 'docSidebar',
      sidebarId: 'tutorial2Sidebar',
      docsPluginId: 'docs2',
      position: 'left',
      label: 'Tutorial2',
    },
    // ...其他导航项
  ],
},
```

两个关键属性：

- `sidebarId: 'tutorial2Sidebar'`：指向 `sidebars2.js` 里定义的侧边栏；
- `docsPluginId: 'docs2'`：**显式声明**这个导航项属于 `docs2` 插件实例。这一行是防止链接解析歧义的保险，即使侧边栏文件已经分开，也建议始终写上。

## 第四步：丰富左侧菜单（多目录/多级分类）

侧边栏是 `autogenerated` 模式，`docs2/` 下的每个**子目录**会自动成为一个可折叠的分类，无需再改任何配置。只需按如下结构组织文件：

```
docs2/
├── intro.mdx                  # 顶层文档（sidebar_position: 1）
├── guide/                     # 分类一：入门指南
│   ├── _category_.json
│   ├── getting-started.mdx
│   └── concepts.mdx
├── advanced/                  # 分类二：进阶用法
│   ├── _category_.json
│   ├── tips.mdx
│   └── best-practices.mdx
└── api/                       # 分类三：API 参考
    ├── _category_.json
    └── config.mdx
```

每个分类目录放一个 `_category_.json`，例如 `guide/_category_.json`：

```json
{
  "label": "入门指南",
  "position": 2,
  "link": {
    "type": "generated-index",
    "description": "快速了解 Tutorial2 的基础内容。"
  }
}
```

字段说明：

- `label`：侧边栏里显示的分类名称；
- `position`：分类之间的排序（顶层文档 `intro.mdx` 用 front matter 里的 `sidebar_position: 1` 排在最前）；
- `link.type: 'generated-index'`：让分类本身可点击，Docusaurus 会自动生成一个分类索引页（路由形如 `/docs2/category/入门指南`），`description` 会展示在该索引页上。

分类内部文档的排序由各文档 front matter 的 `sidebar_position` 决定。如果需要**多级菜单**，在分类目录里再嵌套子目录并放置新的 `_category_.json` 即可，自动生成机制会递归处理。

## 验证

依次执行以下检查：

```bash
npm run build
```

1. 构建成功无报错（无路由冲突、无断链）；
2. 确认 `build/docs2/` 下生成了对应页面的 `index.html`；
3. 运行 `npm start`，导航栏出现 **Tutorial2**，点击跳转到 `/docs2/intro`；
4. `/docs2` 页面左侧出现 `tutorial2Sidebar` 自动生成的多级菜单；
5. 原有的 Tutorial（`/docs/intro`）和 Blog 一切正常，不受影响。

## 常见问题速查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 点 Tutorial2 跳到了 `/docs/intro` | 两个实例共用了 sidebar 文件，sidebarId 被默认实例抢先注册 | 每个实例独立 sidebar 文件 + 导航项加 `docsPluginId` |
| 构建报路由冲突 | `routeBasePath` 与默认 `docs` 相同 | 改成不同的前缀，如 `docs2` |
| 构建报 docs 目录为空 | 插件实例的 `path` 目录内没有任何文档 | 先创建至少一个 md/mdx 文档 |
| 侧边栏没出现新分类 | 新目录缺少文档或 `_category_.json` 写错 | 确认目录内有文档文件，JSON 格式正确 |

## 总结

新增一个导航栏文档区，完整改动清单如下：

1. **新建** `docs2/intro.mdx` —— 首篇文档（目录不能为空）；
2. **新建** `sidebars2.js` —— docs2 实例专属侧边栏，定义 `tutorial2Sidebar`；
3. **修改** `docusaurus.config.js` 两处：
   - `plugins` 中注册 `@docusaurus/plugin-content-docs` 第二实例（`id: 'docs2'`、`path: 'docs2'`、`routeBasePath: 'docs2'`、`sidebarPath: './sidebars2.js'`）；
   - `navbar.items` 中新增 `docSidebar` 类型导航项，并显式指定 `docsPluginId: 'docs2'`；
4. **按需** 在 `docs2/` 下添加子目录 + `_category_.json` 扩展多级菜单。

记住核心原则：**一个文档区 = 一个 docs 插件实例 = 一个独立 sidebar 文件 + 一个独立路由前缀**。
